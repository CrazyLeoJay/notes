## 模块化定义

其实模块化简单粗暴一点，我更愿意直接称为工厂模式。

因为模块化本质就是通过拆分需求，建立一个一个不同功能类型的工厂。有时候，某些工厂只有一个实现，但是，不是说它非得有多种实现时才能使用，我们可以用来更新旧代码逻辑修复bug。所以得从设计角度上看待这个模块，它是某个**最小的设计拆分**的实现，并且这个实现和其他实现有**非常低的耦合**。

这里我直接采用工厂实现方式，通过定义接口的方式直接定义工厂。然后通过**接口多继承**的方式，将所有工厂集合为一个总工厂。

当然我也可以通过构建**抽象工厂**的方式，强制定义实现抽象工厂时，去实现子工厂的实例（可以通过注解编程直接生成模板代码）。

由于是这篇文章主要是正对于**广告手游SDK**的实现，所以使用第一种**接口多继承**方式，这样在对外实现上，提供一个类即。

> 一般SDK设计就提供一个单例，让游戏方调用，比较简单，如果想要复杂点也不是不可以，只要老板没问题。

所以在设计接口时需要注意两点：

- 类名要唯一，即使不同包路径，方式在使用时存在歧义
- 实现方法需要在所有模块中唯一，否则在调用时不知道会调用谁。所以一般每个工厂接口的方法都有一个固定的前缀。

即使使用抽象工厂模式，我也建议保持上述问题。因为有时候我们可能需要在一个模块中实现多个工厂调用，如果工厂方法和参数都相同，会出现意想不到的问题。
